# 就活用ポートフォリオサイトのセットアップ（magicuidesign/portfolio ベース）

## Context
ユーザーはエンジニア就活用のポートフォリオサイトを新規作成したい。`/Users/shoei-y/projects/portfolio` はまだ空（gitリポジトリでもない）。
候補を比較した結果、以下の理由で **magicuidesign/portfolio**（MITライセンス）を採用することが決定した。

- Next.js + shadcn/ui + Magic UI の組み合わせで、就活サイトとして見た目の完成度が高い
- 設定ファイル1つ（`src/data/resume.tsx`）を編集するだけで経歴・スキル・プロジェクトを反映できる構成
- MDXベースのブログ機能、ダークモード、レスポンシブ対応が標準で入っている

環境確認済み：`mise` 導入済み（v2026.8.6）。現状グローバルはNode v20.18.1で`~/.config/mise/config.toml`により管理されているが、Node20は2026年4月にEOL済み。本プロジェクトでは`mise`でプロジェクトローカルにNode24系（手元に24.19.0がインストール済み・Active LTS）を固定する。npm 10.8.2、git 2.55.0は確認済み。pnpmは未インストールだが、Node同梱のcorepackで導入可能。

## 実装ステップ

1. **テンプレートの取り込み**
   - `git clone https://github.com/magicuidesign/portfolio .`（既存の空ディレクトリにclone）
   - オリジナルの履歴・リモートを持ち込まないよう、`rm -rf .git && git init` でこのユーザー自身の新規リポジトリとして再初期化する

2. **Node.jsバージョンをmiseで固定**
   - プロジェクト直下に `mise.toml` を作成し、`[tools]` に `node = "24.19.0"` を指定（既にローカルにインストール済みのバージョンを流用、追加ダウンロード不要）
   - `mise install` で反映を確認し、プロジェクト内で `node -v` が24系になることを確認（グローバル設定や他プロジェクトのNode20環境には影響しない）

3. **依存関係のインストール**
   - `corepack enable && corepack prepare pnpm@latest --activate` でpnpmを有効化
   - `pnpm install` を実行（corepackが使えない場合は `npm install` にフォールバック）

4. **動作確認**
   - `pnpm dev`（またはnpm run dev）でローカル起動し、トップページ・ブログページが表示されることを確認

5. **個人情報への差し替え（要ユーザー提供情報）**
   - 主編集対象: `src/data/resume.tsx` — 氏名・連絡先・学歴・職歴/インターン経験・スキル・プロジェクト一覧・SNS/GitHubリンクを実データに置換
   - `public/` 配下のアバター画像・OGP画像をユーザー自身のものに差し替え
   - サンプルのブログ記事（MDX）が残っていれば削除 or 自分の記事に置換
   - `README.md` をテンプレート由来の説明から、自分のポートフォリオ用の説明に書き換え

6. **仕上げ**
   - `pnpm lint` でコード品質チェック
   - LICENSE(MIT)は残しつつ著作権表示など必要箇所を確認
   - デプロイはVercel推奨（"Deploy with Vercel"連携）。ユーザーのVercelアカウントでの連携作業は本人操作が必要なため、手順を案内する形で対応

## 対象ファイル
- `mise.toml`（プロジェクトローカルのNode.jsバージョン固定）
- `package.json` / `pnpm-lock.yaml`（依存関係）
- `src/data/resume.tsx`（プロフィール・経歴・プロジェクトの単一設定ファイル）
- `public/`（アバター・OGP画像などの静的アセット）
- MDXブログ記事ディレクトリ（テンプレートの `content/` 系ディレクトリ、実ファイル構成はclone後に確認）
- `README.md`

## 検証方法
- `pnpm install` がエラーなく完了すること
- `pnpm dev` でローカルサーバーが起動し、トップページ・プロジェクト一覧・ブログ（ある場合）がレイアウト崩れなく表示されること
- `pnpm lint` が通ること
- ステップ4の差し替え後、テンプレートのプレースホルダー文言（サンプル氏名・ダミー経歴等）が残っていないことを目視確認

## 次のアクションで必要になるユーザー提供情報
実装を進める中で、以下をユーザーから聞き取る想定：
- 氏名・大学/学部・卒業予定時期・連絡先（メール等）
- 職歴/インターン/研究内容などの経歴情報
- アピールしたいプロジェクト（タイトル・概要・使用技術・リンク）
- スキルセット（言語・フレームワーク等）
- GitHub/X(Twitter)/LinkedInなどのリンク
- プロフィール画像
